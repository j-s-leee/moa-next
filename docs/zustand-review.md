# Zustand (전역 상태 관리) 도입 시점 검토

## 현재 상태 분석

### 현재 문제점

**1. 가계부 목록 중복 Fetch**
- `app/book/page.tsx`: 가계부 목록 fetch
- `app/book/budget/page.tsx`: 또 다시 가계부 목록 fetch
- `app/book/add/page.tsx`: 또 다시 가계부 목록 fetch
- 각 컴포넌트마다 동일한 API를 호출하고 있음

**2. 현재 선택된 가계부 정보가 각 컴포넌트에 분산**
```typescript
// app/book/page.tsx
const [bookId, setBookId] = useState<string | null>(null);

// app/book/budget/page.tsx
const [bookId, setBookId] = useState<string | null>(null);

// app/book/add/page.tsx
const [bookId, setBookId] = useState<string | null>(null);
```

**3. 사용자 정보도 각 컴포넌트에서 개별 fetch**
- `components/nav-user.tsx`: 사용자 프로필 fetch
- `app/settings/page.tsx`: 또 다시 사용자 프로필 fetch

**현재는 개인 가계부만 있어서 문제가 크지 않지만**, 공동 가계부가 추가되면 심각한 문제가 됨.

## Phase별 필요성 분석

### Phase 4.5 (현재): 필요 없음 ❌

**이유**:
- 개인 가계부만 존재
- 각 컴포넌트가 개별적으로 처리해도 문제 없음
- 가계부 전환 기능 없음
- 중복 fetch는 있지만 크게 문제되지 않음

**결론**: 도입 불필요

---

### Phase 5 (대시보드): 선택적 필요 ⚠️

**필요할 수 있는 경우**:
- 통합 대시보드에서 "개인/공동/전체" 필터 기능
- 여러 가계부 데이터를 한 번에 표시
- 대시보드에서 가계부 전환 기능

**필요하지 않은 경우**:
- 대시보드가 단순히 현재 가계부의 통계만 표시
- 가계부 전환은 사이드바에서 URL 변경으로 처리

**결론**: 대시보드 설계에 따라 결정

---

### Phase 6 (공동 가계부): 필수 필요 ✅

**반드시 필요한 이유**:

1. **가계부 전환 기능**
   ```
   사이드바에서 "개인 가계부" 또는 "공동 가계부" 선택
   → 선택한 가계부 정보를 모든 컴포넌트에서 공유해야 함
   ```

2. **가계부 목록 관리**
   ```
   - 개인 가계부 목록
   - 공동 가계부 목록
   - 현재 선택된 가계부
   → 한 번만 fetch하고 전역에서 공유
   ```

3. **사용자/파트너 정보**
   ```
   - 현재 사용자 정보
   - 파트너 정보 (공동 가계부 멤버)
   - 권한 정보
   → 여러 컴포넌트에서 공유 필요
   ```

4. **실시간 동기화**
   ```
   - 사용자 A가 지출 추가 → 사용자 B 화면 자동 업데이트
   - 현재 가계부 컨텍스트를 전역에서 관리해야 함
   ```

5. **통합 뷰 필터**
   ```
   - 전체 (개인 + 공동)
   - 개인만
   - 공동만
   → 필터 상태를 전역에서 관리
   ```

**결론**: Phase 6 시작 전에 반드시 도입 필요

## TanStack Query와의 관계

### TanStack Query만으로는 부족한 이유

**TanStack Query의 역할**:
- 서버 상태(데이터) 관리
- 캐싱 및 동기화
- API 호출 최적화

**부족한 부분**:
- 클라이언트 상태(UI 상태) 관리
  - 현재 선택된 가계부
  - 필터 상태 (전체/개인/공동)
  - 사이드바 열림/닫힘 상태
  - 사용자 정보 (서버에서 가져오지만 UI에서 자주 사용)

**Zustand의 역할**:
- 클라이언트 상태 관리
- UI 상태 공유
- TanStack Query와 함께 사용 시 강력한 조합

**조합 예시**:
```typescript
// Zustand: 현재 가계부 관리
const { currentBook } = useBookStore();

// TanStack Query: 해당 가계부의 데이터 fetch
const { data: expenses } = useQuery({
  queryKey: ['expenses', currentBook?.id],
  queryFn: () => fetchExpenses(currentBook.id),
});
```

## 참고: TanStack Query와의 조합

Zustand는 TanStack Query와 함께 사용할 때 가장 강력합니다:

```typescript
// Zustand: 클라이언트 상태 (현재 가계부)
const { currentBook } = useBookStore();

// TanStack Query: 서버 상태 (데이터)
const { data: expenses } = useQuery({
  queryKey: ['expenses', currentBook?.id],
  queryFn: () => fetchExpenses(currentBook.id),
});

// 가계부 전환 시 자동으로 쿼리 재실행
const handleBookChange = (bookId: string) => {
  setCurrentBook(bookId);
  // TanStack Query가 자동으로 해당 가계부 데이터를 fetch
};
```

**권장 순서**:
1. Phase 4.5: TanStack Query 도입
2. Phase 5: 대시보드 개발 (필요 시 Zustand 도입)
3. Phase 5.5 또는 Phase 6 전: Zustand 도입 (공동 가계부 준비)
