# The Moa 브레인스토밍

## 목표

- 개인 가계부 뿐만 아니라 부부의 공동 가계부도 한 서비스에서 관리
- 월단위, 연단위 지출을 예상해 예산을 세우고 계획적 소비를 하도록 도움
- 서비스를 이용하다보면 다음달 혹은 내년에 어떤 카테고리에 얼마씩 예산을 잡아야할지 예측 가능하게 하여 중장기적인 저축을 도움
- 공동 가계부의 경우 오너, 게스트 개념이 아닌 부부가 함께 관리 가능
- 동일 서비스를 모바일과 데스크탑에서 모두 이용 가능. 모바일에선 쉽게 내역을 입력하고, 데스크탑에선 보다 큰 화면으로 한눈에 정리된 내용을 볼 수 있도록 함

## 개인

### 수입

- 고정수입
  - 매주
  - 매월
  - 매년
- 변동수입

### 월정기지출

- 매월 고정금액이므로 지출로 잡힘
- 예: 통신비, 월세, 보험 등

### 변동지출

- 매월 발생하는 지출이지만 금액은 고정이 아님
- 예: 관리비, 공과금

### 비정기지출

- 매월 정기적이지 않지만 연간 예산을 세워두고 지출함.
- 토탈 예산 / 12를 예산저축? 비상금저축? 으로 따로 잡아야함.

### 일반지출

- 예산이 없는 지출? 있으면 안됨
- 용돈이나 생활비 명목의 예산을 잡고 예산 내 사용하도록 관리필요 → 변동지출과 동일하다고 봐야할지도

### 카테고리

- 예산과 별개로 필요한 이유?
  - 동일 카테고리에 매월 또는 매년 예산이 다를 수 있음.
    예: 올해 예산 설정 후 사용해보니 모자라서 내년 예산 변경 시 이전 예산 정보를 알 수 없음
  - 그럼 1년 예산을 잡았다가 중간에 수정하면 어쩔?

## 검토 의견

### 지출 타입 분류 검토

#### 1. 현재 분류의 문제점

**월정기지출 vs 변동지출의 경계가 모호함**

- 두 타입 모두 "매월 발생"이라는 공통점이 있음
- 실제로는 "예산 설정 방식"의 차이로 보는 것이 더 명확할 수 있음
  - 고정 예산: 매월 동일 금액 (월정기지출)
  - 변동 예산: 매월 금액이 다를 수 있지만 범위/한도 설정 (변동지출)

**비정기지출의 정의가 불명확**

- "연간 예산을 세워두고 지출함" → 이는 예산 설정 방식이지 지출 타입이 아님
- 실제로는 "연간 총액 예산"을 월별로 분산하는 방식
- 예: 연간 의류비 120만원 → 월 10만원씩 저축, 필요시 사용

**일반지출의 존재 이유가 불명확**

- "예산이 없는 지출? 있으면 안됨" → 이는 타입이 아니라 관리 상태
- 용돈/생활비도 결국 변동지출로 관리 가능
- 제안: 일반지출 타입 제거, 모든 지출은 예산과 연동

#### 2. 개선 제안: 지출 타입 재정의

**타입 1: 고정지출 (Fixed Expense)**

- 매월 동일 금액이 발생하는 지출
- 예: 통신비, 월세, 보험료, 구독료
- 예산 설정: 월별 고정 금액

**타입 2: 변동지출 (Variable Expense)**

- 매월 발생하지만 금액이 변동하는 지출
- 예: 관리비, 공과금, 식비, 교통비
- 예산 설정: 월별 예산 범위 또는 한도

**타입 3: 연간예산지출 (Annual Budget Expense)**

- 연간 총액 예산을 설정하고 필요시 지출
- 예: 의류비, 가전제품 구매, 여행비, 선물비
- 예산 설정: 연간 총액 → 자동으로 월별 저축액 계산
- 특징: 월별로 저축액만큼 예산이 누적됨 (사용 시 차감)

**타입 4: 일회성지출 (One-time Expense)**

- 계획되지 않은 긴급/비상 지출
- 예: 병원비, 긴급 수리비
- 예산 설정: 비상금에서 차감 또는 별도 관리

### 카테고리와 예산의 분리 검토

#### 1. 카테고리의 필요성

**카테고리는 반드시 필요함**

- 지출의 분류/분석을 위한 기본 단위
- 예산과는 독립적으로 존재해야 함
- 이유:
  1. **시계열 분석**: 동일 카테고리의 과거 지출 추이 분석
  2. **예산 변경 추적**: 카테고리별 예산 변경 이력 관리
  3. **유연한 예산 관리**: 기간별로 다른 예산 설정 가능

#### 2. 카테고리-예산 관계 모델

**제안 구조:**

```
카테고리 (Category)
  ├─ 식비
  ├─ 교통비
  └─ 의류비
      └─ 예산 (Budget) - 기간별로 다름
          ├─ 2024년 예산: 120만원/년
          ├─ 2025년 예산: 150만원/년 (수정됨)
          └─ 2024년 6월 예산 수정: 130만원/년 (중간 수정)****
```

**예산 수정 시나리오 처리:**

1. **연간 예산 중간 수정**

   - 수정 전 예산: 이력으로 보관
   - 수정 후 예산: 남은 기간에 적용
   - 예: 1월에 120만원 설정 → 6월에 130만원으로 수정
     - 1~5월: 120만원 기준으로 집계
     - 6~12월: 130만원 기준으로 집계
     - 연간 총액: (120만원 × 5/12) + (130만원 × 7/12) = 계산

2. **예산 이력 관리**
   - 각 예산 변경마다 타임스탬프와 변경 사유 기록
   - 과거 예산 정보는 항상 조회 가능
   - 예산 변경 추이 그래프로 시각화 가능

#### 3. 데이터 모델 제안

```typescript
// 카테고리 (변경 불가능한 분류)
interface Category {
  id: string;
  name: string;
  icon?: string;
  type: "expense" | "income";
}

// 예산 (기간별로 설정)

  period: "monthly" | "yearly";
  amount: number;
  startDate: Date;
  endDate: Date;
  createdAt: Date;
  updatedAt: Date;
  // 중간 수정 시 이전 예산 참조

// 지출 내역
interface Expense {
  id: string;
  categoryId: string;
  amount: number;
  date: Date;
  description: string;
  // 예산과의 연결 (선택적)
  budgetId?: string;
```

### 추가 고려사항

1. **예산 vs 실제 지출 추적**

   - 각 카테고리별로 예산 대비 실제 지출 추적
   - 월별/연별 집계 및 시각화

2. **예산 알림**

   - 예산 초과 시 알림
   - 예산 대비 사용률 경고 (예: 80%, 100%)

3. **예산 자동 제안**
   - 과거 지출 데이터 기반으로 다음 달/다음 해 예산 제안
   - 목표 7번 항목과 연계

## 추가 질문에 대한 답변

### 1. 변동지출은 매번 예산을 초과하거나 못미치게 사용하는가?

**아니요. 변동지출의 의미를 명확히 해야 합니다.**

**변동지출의 개념:**

- "변동"은 **실제 지출 금액이 매월 달라진다**는 의미
- 예산은 **목표치/한도**로 설정됨
- 예산을 초과하거나 못미치는 것은 **관리 결과**이지 타입의 특성이 아님

**예시:**

- 식비 카테고리 (변동지출)
  - 1월 예산: 50만원 → 실제 지출: 48만원 (예산 내)
  - 2월 예산: 50만원 → 실제 지출: 52만원 (예산 초과)
  - 3월 예산: 50만원 → 실제 지출: 45만원 (예산 내)

**변동지출의 특징:**

- 매월 발생하지만 금액이 일정하지 않음
- 예산은 평균치 또는 한도를 설정
- 실제 지출이 예산보다 많거나 적을 수 있음 (정상적인 현상)
- 예산 초과 시 알림/경고 제공
- 예산 미달 시 다음 달로 이월하거나 분석 자료로 활용

**고정지출과의 차이:**

- 고정지출: 예산 = 실제 지출 (거의 동일)
- 변동지출: 예산 ≠ 실제 지출 (매월 다를 수 있음)

### 1-1. 변동지출과 고정지출을 구별하는 기준은 무엇인가?

**제안: 자동 감지 + 사용자 확인 방식**

#### 문제점: 사용자가 직접 타입을 정하는 것의 한계

**사용자 직접 선택의 문제:**

- 초기 사용자는 타입을 구분하기 어려움
- 같은 카테고리라도 사용자마다 다를 수 있음 (예: 통신비가 고정일 수도, 변동일 수도)
- 타입 선택이 부담스러워 서비스 진입 장벽이 됨

#### 해결 방안: 자동 감지 + 사용자 확인

**1단계: 자동 감지 (시스템이 판단)**

```typescript
// 카테고리 타입 자동 감지 로직
function detectCategoryType(
  categoryId: string,
  expenses: Expense[]
): "fixed" | "variable" {
  // 최근 3개월 데이터 분석
  const recentExpenses = getRecentExpenses(categoryId, expenses, 3);

  if (recentExpenses.length < 3) {
    return "variable"; // 데이터 부족 시 기본값
  }

  const amounts = recentExpenses.map((e) => e.amount);
  const variance = calculateVariance(amounts);
  const mean = calculateMean(amounts);

  // 변동계수(CV) 계산: 표준편차 / 평균
  const coefficientOfVariation = Math.sqrt(variance) / mean;

  // 변동계수가 5% 미만이면 고정지출로 판단
  if (coefficientOfVariation < 0.05) {
    return "fixed";
  }

  return "variable";
}
```

**감지 기준:**

- **고정지출 판단**: 최근 3개월 지출 금액의 변동계수 < 5%
  - 예: 통신비가 3개월 연속 5만원, 5만원, 5만원 → 고정지출
- **변동지출 판단**: 변동계수 ≥ 5% 또는 데이터 부족
  - 예: 식비가 3개월 연속 48만원, 52만원, 45만원 → 변동지출

**2단계: 사용자 확인 및 수정**

- 시스템이 자동 감지한 타입을 제안
- 사용자가 확인하거나 수정 가능
- 타입 변경 시 예산 설정 방식도 자동 조정

**UI 흐름:**

```
1. 카테고리 생성 시
   - 사용자가 카테고리 이름만 입력
   - 시스템이 자동으로 타입 감지 (초기에는 "변동지출" 기본값)

2. 지출 기록 후 (3개월 데이터 쌓임)
   - 시스템이 타입 재분석
   - "통신비가 고정지출로 보입니다. 변경하시겠습니까?" 알림
   - 사용자가 확인/거부

3. 수동 변경
   - 카테고리 설정에서 타입 변경 가능
   - 타입 변경 시 예산 설정 방식 안내
```

**데이터 모델 반영:**

```typescript
interface Category {
  id: string;
  name: string;
  icon?: string;
  type: "expense" | "income";
  expenseType?: "fixed" | "variable" | "annual" | "one-time"; // 지출 타입
  autoDetectedType?: "fixed" | "variable"; // 자동 감지된 타입
  lastTypeCheckDate?: Date; // 마지막 타입 확인 날짜
}
```

**예산 설정 방식 자동 조정:**

- 고정지출로 변경 시: 예산 입력 필드가 "월 고정 금액"으로 변경
- 변동지출로 변경 시: 예산 입력 필드가 "월 예산 범위" 또는 "월 한도"로 변경

### 2. 카테고리는 예산을 필수로 설정해야 하는가?

**제안: 예산 설정은 선택사항이지만, 강력히 권장**

**예산을 필수로 하지 않는 이유:**

1. **초기 사용자 진입 장벽**

   - 처음 사용하는 사용자는 모든 카테고리에 예산을 설정하기 부담스러울 수 있음
   - 먼저 지출을 기록하고, 나중에 예산을 설정하는 흐름이 자연스러움

2. **일부 카테고리는 예산 설정이 어려움**

   - 새로 생긴 카테고리 (예: 새로운 취미)
   - 드물게 사용하는 카테고리 (예: 선물, 기부)
   - 예측 불가능한 카테고리 (예: 의료비, 긴급 수리)

3. **점진적 예산 관리**
   - 사용자가 서비스를 사용하면서 점차 예산을 설정하도록 유도
   - 과거 데이터가 쌓이면 예산 자동 제안 기능 활용

**예산 설정을 권장하는 방법:**

1. **UI/UX 설계**

   - 예산 미설정 카테고리에 "예산 설정하기" 배지 표시
   - 대시보드에서 예산 미설정 카테고리 강조
   - 예산 설정 가이드 제공

2. **기능적 인센티브**

   - 예산이 설정된 카테고리만 예산 대비 분석 제공
   - 예산 설정 시 알림/경고 기능 활성화
   - 예산 설정 카테고리 비율을 시각화하여 동기 부여

3. **자동 제안**
   - 3개월 이상 지출 데이터가 쌓인 카테고리에 예산 제안
   - 사용자가 쉽게 승인할 수 있는 UI 제공

**데이터 모델 반영:**

```typescript
interface Category {
  id: string;
  name: string;
  icon?: string;
  type: "expense" | "income";
  // 예산 설정 여부는 Budget 존재 여부로 판단
}

interface Budget {
  id: string;
  categoryId: string; // 카테고리와의 연결 (선택적)
  period: "monthly" | "yearly";
  amount: number;
  startDate: Date;
  endDate: Date;
  // 예산이 없어도 카테고리는 존재 가능
}
```

### 3. 공동 가계부 구성 제안

**핵심 원칙:**

- 개인 가계부와 공동 가계부는 **별도로 관리**하되 **통합 뷰** 제공
- 각 가계부는 독립적인 카테고리, 예산, 지출 내역을 가짐
- 통합 대시보드에서 개인 + 공동을 함께 볼 수 있음

#### 데이터 구조 제안

```typescript
// 가계부 타입
interface Book {
  id: string;
  name: string;
  type: "personal" | "shared";
```

#### UX 시나리오별 구성

**시나리오 1: 개인 가계부만 사용하다가 공동 가계부 추가**

1. **초기 상태**

   - 사용자 A: 개인 가계부 1개 (수입 300만원, 예산 설정 완료)
   - 사용자 B: 개인 가계부 1개 (수입 250만원, 예산 설정 완료)

2. **공동 가계부 생성**

   - 사용자 A가 "공동 가계부 만들기" 클릭
   - 사용자 B 초대 (이메일/링크)
   - 사용자 B 승인 시 공동 가계부 생성
   - 각자의 개인 가계부는 그대로 유지

3. **기존 예산 설정 처리 (핵심 문제)**

   **문제 상황:**

   - 사용자 A가 개인 수입 300만원 기준으로 예산을 설정해둠
   - 공동 가계부 생성 시 개인 예산을 어떻게 처리할까?

   **해결 방안: 개인 예산은 그대로 유지, 공동 예산은 새로 설정**

   **원칙:**

   - 개인 가계부의 예산은 **절대 자동으로 변경하지 않음**
   - 공동 가계부는 **새로운 가계부**이므로 예산도 새로 설정
   - 사용자가 **선택적으로** 개인 예산을 참고하여 공동 예산 설정

   **UX 흐름:**

   ```
   1. 공동 가계부 생성 완료 후
      → "공동 가계부 예산 설정하기" 가이드 화면 표시

   2. 예산 설정 옵션 제공:
      a) "개인 예산 참고하기" (권장)
         - 사용자 A의 개인 예산을 보여줌
         - 사용자 B의 개인 예산도 함께 보여줌 (선택적)
         - 각 카테고리별로 개인 예산 합산 또는 평균 제안
         - 사용자가 확인/수정 후 공동 예산으로 설정

      b) "처음부터 설정하기"
         - 빈 상태에서 공동 예산 설정
         - 개인 예산 정보는 보여주되, 자동 적용하지 않음

      c) "나중에 설정하기"
         - 공동 가계부 사용 시작
         - 예산 없이 지출 기록 가능
         - 나중에 예산 설정 가능
   ```

   **개인 예산 참고 시 고려사항:**

   - **수입 기준 조정 필요**

     - 개인 수입 합산 (300만원 + 250만원 = 550만원)이 공동 수입은 아님
     - 공동 가계부 수입은 별도로 설정 (예: 공동 생활비 400만원)
     - 개인 예산을 그대로 합산하면 예산 초과 위험

   - **카테고리별 처리 방식**

     ```
     예시: 식비 카테고리

     사용자 A 개인 예산: 50만원/월
     사용자 B 개인 예산: 45만원/월

     공동 예산 제안 옵션:
     1. 합산: 95만원/월 (개인 예산 합산)
        → 문제: 공동 생활 시 식비가 개인 합산보다 적을 수 있음

     2. 평균: 47.5만원/월 (개인 예산 평균)
        → 문제: 공동 생활 시 규모의 경제로 더 적을 수도 있음

     3. 사용자 직접 입력: 80만원/월 (공동 생활 기준)
        → 권장: 공동 생활의 특성을 반영
     ```

   - **자동 제안 로직**

     ```typescript

       personalBudgets: Budget[], // 사용자 A의 개인 예산

         });
       }

     }
     ```

   **4. 실제 사용 패턴 분석**

   **⚠️ 중요: 수입 분리 방식의 올바른 이해**

   **잘못된 이해 (사용자 질문의 시나리오):**

   ```
   ❌ 시나리오 1:
   - 개인 수입: 30만원/월 (용돈)

   - 개인 수입: 30만원/월 (용돈)
   - 공동 수입: 300만원/월 (급여)
   - 공동 예산: 30만원/월 (사용자A 용돈) ← 문제: 공동 예산에 개인 용돈?
   ```

   **올바른 이해: 수입은 실제 수입을 기록, 예산은 사용 계획**

   **핵심 개념:**

   - **수입**: 실제로 들어오는 돈 (급여, 용돈 등)
   - **예산**: 그 돈을 어떻게 사용할 계획인지
   - **개인 가계부**: 개인이 혼자 사용하는 돈 관리
   - **공동 가계부**: 부부가 함께 사용하는 돈 관리

   **패턴 A: 수입 분리 방식 (권장) - 올바른 예시**

   ```
   [사용자 A의 상황]

   실제 수입:
   - 급여: 300만원/월 (실제 계좌로 들어옴)

   개인 가계부:
   - 개인 수입: 300만원/월 (급여 전체를 개인 수입으로 기록)
   - 개인 예산: 100만원/월 (개인 용돈, 취미, 개인 지출)

   공동 가계부:
   - 공동 수입: 200만원/월 (급여 중 200만원을 공동 생활비로 이체)
   - 공동 예산: 200만원/월 (공동 생활비, 공과금, 식비 등)

   → 개인 수입 300만원 중 100만원은 개인 용돈, 200만원은 공동 생활비
   → 공동 예산에는 "개인 용돈"이 아니라 "공동 생활비"가 들어감
   ```

   ```
   [사용자 A의 실제 상황]

   월급 300만원이 계좌로 들어옴

   [공동 가계부 설정]
   - 공동 수입: 200만원/월 (급여 중 공동 생활비로 이체)
   - 공동 예산:
     * 식비: 80만원/월
     * 공과금: 50만원/월
     * 월세: 50만원/월
     * 공동 저축: 20만원/월
     * 합계: 200만원/월

   [실제 사용]
   - 개인 가계부: 용돈 50만원, 취미 30만원, 개인 저축 20만원 사용
   - 공동 가계부: 식비, 공과금, 월세 등 공동 지출 기록
   ```

   **패턴 A-1: 수입을 처음부터 분리하는 방식 (패턴 A의 변형)**

   ```
   [사용자 A의 상황]

   실제 수입:
   - 급여: 300만원/월

   [설정 방식]
   - 개인 수입: 100만원/월 (용돈으로 분리)
   - 공동 수입: 200만원/월 (공동 생활비로 분리)

   [개인 가계부]
   - 개인 수입: 100만원/월
   - 개인 예산: 100만원/월 (용돈, 취미 등)

   [공동 가계부]
   - 공동 수입: 200만원/월
   - 공동 예산: 200만원/월 (공동 생활비)

   → 수입을 처음부터 분리하여 관리
   → 각 가계부의 수입 합계 = 실제 수입 (300만원)
   → 패턴 A와 동일한 결과, 설정 방식만 다름
   ```

   **패턴 A-2: 공동 수입을 별도로 설정하지 않는 방식 (패턴 A의 변형)**

   ```
   [사용자 A의 상황]

   실제 수입:
   - 급여: 300만원/월

   [개인 가계부]
   - 개인 수입: 300만원/월 (급여 전체)
   - 개인 예산: 100만원/월 (개인 용돈)

   [공동 가계부]
   - 공동 수입: 0만원/월 (설정하지 않음)
   - 공동 예산: 200만원/월 (공동 생활비)

   → 공동 가계부는 예산만 설정하고 수입은 설정하지 않음
   → 공동 지출은 개인 수입에서 지출하는 것으로 간주
   → 통합 뷰에서 개인 수입 300만원 - 개인 예산 100만원 - 공동 예산 200만원 = 0만원
   ```

   **요약: 올바른 수입/예산 설정 방식**

   **핵심 원칙:**

   1. **수입 = 실제로 들어오는 돈** (급여, 용돈 등)
   2. **예산 = 그 돈을 어떻게 사용할 계획**
   3. **개인 예산 = 개인 용돈, 개인 취미 등**
   4. **공동 예산 = 공동 생활비, 공과금 등** (개인 용돈 제외)

   **올바른 설정 예시 (사용자 A, 급여 300만원/월):**

   ```
   ✅ 올바른 방식 1 (패턴 A):
   - 개인 수입: 300만원/월 (급여 전체)
   - 개인 예산: 100만원/월 (개인 용돈, 취미)

   ✅ 올바른 방식 2 (패턴 A-1):
   - 개인 수입: 100만원/월 (용돈으로 분리)
   - 개인 예산: 100만원/월 (개인 용돈, 취미)
   - 공동 수입: 200만원/월 (공동 생활비로 분리)
   - 공동 예산: 200만원/월 (공동 생활비, 공과금, 식비 등)

   - 개인 수입: 300만원/월 (급여 전체)

   ```

   **사용자가 제시한 시나리오의 문제점:**

   ```
   ❌ 잘못된 시나리오 1:
   - 개인 수입: 30만원/월 (용돈)
   - 공동 수입: 270만원/월 (급여)
   - 공동 예산: 30만원/월 (사용자A 용돈) ← 문제!

   ❌ 잘못된 시나리오 2:
   - 개인 수입: 30만원/월 (용돈)
   - 공동 수입: 300만원/월 (급여)
   - 공동 예산: 30만원/월 (사용자A 용돈) ← 문제!

   문제점:
   1. 공동 예산에 "개인 용돈"이 포함됨
      → 공동 예산은 공동 생활비만 포함해야 함
      → 개인 용돈은 개인 예산에만 포함

   2. 수입과 예산의 개념 혼동
      → 수입: 실제로 들어오는 돈 (급여 300만원)
      → 예산: 그 돈을 어떻게 사용할 계획
      → 공동 예산에 "용돈"이 아니라 "공동 생활비"가 들어가야 함

   3. 수입 합계가 실제 수입과 맞지 않음
      → 시나리오 1: 30만원 + 270만원 = 300만원 (맞음)
      → 시나리오 2: 30만원 + 300만원 = 330만원 (실제 수입 초과)
   ```

   **⚠️ 중요: 방식1의 총 수입 계산 문제**

   **문제 상황:**

   ```
   방식1 설정:
   - 개인 수입: 300만원/월 (급여 전체)
   - 공동 수입: 200만원/월 (급여 중 공동 생활비로 이체)

   총 수입 = ?
   - 단순 합산: 300만원 + 200만원 = 500만원 ❌ (잘못됨)
   - 실제 수입: 300만원 ✅ (올바름)
   ```

   **핵심 문제: 공동 수입은 "이체" 개념이지 실제 수입이 아님**

   - 개인 수입 300만원 중 200만원을 공동으로 "이체"한 것
   - 실제로 들어온 돈은 300만원뿐
   - 공동 수입 200만원은 개인 수입에서 이동한 금액

   **해결 방안: 총 수입 계산 시 중복 제거**

   **방법 1: 개인 수입을 기준으로 계산 (권장)**

   ```typescript
   // 총 수입 계산 로직
   function calculateTotalIncome(
     personalIncome: Income[],
     sharedIncome: Income[]
   ): number {
     // 개인 수입의 합계만 계산
     // 공동 수입은 "이체" 개념이므로 총 수입에 포함하지 않음
     const totalPersonalIncome = personalIncome.reduce(
       (sum, income) => sum + income.amount,
       0
     );

     return totalPersonalIncome;
   }

   // 예시:
   // 개인 수입: 300만원
   // 공동 수입: 200만원 (이체)
   // 총 수입: 300만원 ✅
   ```

   **방법 2: 공동 수입을 "이체"로 표시**

   ```typescript
   interface Income {
     id: string;
     bookId: string;
     amount: number;
     period: "monthly" | "yearly";
     source: string;
     type: "actual" | "transfer"; // 실제 수입 vs 이체
     transferredFrom?: string; // 어디서 이체되었는지 (bookId)
     startDate: Date;
     endDate?: Date;
   }

   // 총 수입 계산 시 type이 "actual"인 것만 합산
   function calculateTotalIncome(incomes: Income[]): number {
     return incomes
       .filter((income) => income.type === "actual")
       .reduce((sum, income) => sum + income.amount, 0);
   }
   ```

   **데이터 모델 개선안:**

   ```typescript

   interface Income {
     id: string;
     bookId: string; // 개인 가계부 또는 공동 가계부
     amount: number;
     period: "monthly" | "yearly";
     source: string; // 수입 출처 (급여, 용돈 등)
     incomeType: "actual" | "transfer"; // 실제 수입 vs 이체
     transferredFromBookId?: string; // 이체인 경우 출처 가계부 ID
     startDate: Date;
     endDate?: Date;
   }

   // 총 수입 계산 함수
   function getTotalIncome(
     personalBookId: string,
     sharedBookId: string,
     incomes: Income[]
   ): number {
     // 실제 수입만 합산 (이체 제외)
     const actualIncomes = incomes.filter(
       (income) => income.incomeType === "actual"
     );

     return actualIncomes.reduce((sum, income) => sum + income.amount, 0);
   }

   // 사용 예시
   const personalIncome: Income = {
     id: "1",
     bookId: "personal-book-1",
     amount: 3000000,
     period: "monthly",
     source: "급여",
     incomeType: "actual", // 실제 수입
     startDate: new Date("2024-01-01"),
   };

     bookId: "shared-book-1",
     amount: 2000000,

     incomeType: "transfer", // 이체
     transferredFromBookId: "personal-book-1",
     startDate: new Date("2024-01-01"),
   };

   // 총 수입 계산

     personalIncome,
     sharedIncome,
   ]);
   // 결과: 300만원 (이체는 제외)
   ```

#### 공동 가계부의 특별 고려사항

**1. 수입 관리**

- "개인 수입 2개를 그냥 합산하면 안됨" → 각자의 개인 수입은 개인 가계부에서 관리
- 공동 가계부의 수입: 공동 저축, 공동 투자 수익 등
- 통합 뷰에서 개인 수입 + 공동 수입을 함께 볼 수 있지만, 각각의 출처는 명확히 구분

**2. 지출 입력자 추적**

- 공동 가계부의 모든 지출은 "누가 입력했는지" 기록
- 지출 내역에 입력자 표시
- 통계에서 "A가 입력한 지출", "B가 입력한 지출" 필터링 가능

**3. 예산 설정 권한**

- 공동 가계부의 예산은 양쪽 모두 수정 가능
- 예산 변경 시 상대방에게 알림
- 예산 변경 이력에 변경자 기록

**4. 통합 대시보드**

- 개인 가계부 + 공동 가계부 통합 뷰
- 필터 옵션:
  - 전체 (개인 + 공동)
  - 개인만
  - 공동만
- 카테고리별로 개인/공동 구분 표시

#### 데이터 분리 전략

**왜 분리해야 하는가?**

1. **명확한 소유권**: 각 가계부의 데이터는 명확히 구분
2. **유연한 권한 관리**: 개인 가계부는 본인만, 공동 가계부는 양쪽 모두 접근
3. **독립적인 예산 관리**: 개인 예산과 공동 예산을 별도로 관리
4. **이혼/분리 시나리오**: 나중에 공동 가계부를 분리하거나 삭제할 때 용이

**통합이 필요한 경우:**

- 대시보드에서 전체 재무 상황 파악
- 월별 총 수입/지출 계산
- 카테고리별 통합 분석 (개인 + 공동)
