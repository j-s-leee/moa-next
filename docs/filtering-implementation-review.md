## 구현 제안

### 우선순위 1: 지출 내역 페이지 - 카테고리별 필터링 ⭐⭐⭐

**구현 위치:** `app/book/page.tsx`

**이유:**

1. 정보 구조 문서에 명시된 기능 (`docs/information-architecture.md` 171줄)
2. 사용자가 가장 자주 사용하는 화면
3. 특정 카테고리 지출만 확인하는 니즈가 높음
4. 현재 필터 Drawer에 자연스럽게 추가 가능

**구현 방법:**

- 기존 "필터 및 정렬" Drawer에 카테고리 선택 섹션 추가
- 다중 선택 가능 (여러 카테고리 동시 필터링)
- "전체" 옵션으로 모든 카테고리 선택/해제

**UI 제안:**

```
[필터 및 정렬] Drawer
├─ 유형 (전체/수입/지출) ← 기존
├─ 카테고리 ← 신규 추가
│   ├─ [전체] 버튼
│   ├─ [식비] [교통비] [주거비] ... (체크박스)
│   └─ 스크롤 가능한 목록
└─ 정렬 (날짜순, 금액순) ← 기존
```

**기술적 고려사항:**

- 카테고리 목록은 `/api/book/[bookId]/category?type=expense` API로 조회
- 필터 상태는 URL 쿼리 파라미터로 관리 (공유 가능)
- 필터 적용 시 클라이언트 사이드 필터링 (이미 로드된 데이터 사용)

**예상 작업 시간:** 2-3시간

---

### 우선순위 2: 지출 내역 페이지 - 사용자 정의 기간 필터링 ⭐⭐

**구현 위치:** `app/book/page.tsx`

**이유:**

1. 현재는 월별 선택만 가능하여 특정 기간 조회가 불편함
2. 예: "지난 3개월", "올해 1분기", "특정 날짜 범위" 조회 필요
3. 분석 및 리포트 작성 시 유용

**구현 방법:**

- 월 선택기 옆에 "기간 선택" 버튼 추가
- Drawer로 시작일/종료일 선택 UI 제공
- 또는 미리 정의된 기간 옵션 제공 (최근 7일, 최근 30일, 최근 3개월 등)

**UI 제안:**

```
[월 선택기] [기간 선택 ▼] 버튼
  └─ Drawer
      ├─ 빠른 선택
      │   ├─ 최근 7일
      │   ├─ 최근 30일
      │   ├─ 최근 3개월
      │   └─ 올해
      └─ 사용자 정의
          ├─ 시작일 선택
          └─ 종료일 선택
```

**기술적 고려사항:**

- 기간 선택 시 API 호출 필요 (`/api/book/[bookId]/expense?startDate=...&endDate=...`)
- 월 선택기와 기간 선택은 상호 배타적 (하나만 활성화)
- URL 쿼리 파라미터로 상태 관리

**예상 작업 시간:** 3-4시간

### 우선순위 3: 예산 관리 페이지 - 카테고리별 필터링 ⭐

**구현 위치:** `app/book/budget/page.tsx`

3. 필요 시 검색 기능으로 대체 가능

**구현 방법:**

- 예산 목록 상단에 카테고리 필터 추가
- 드롭다운 또는 체크박스 형태
- 필터링된 예산만 차트에 표시

**UI 제안:**

```
[월/년 선택기] [카테고리 필터 ▼]
  └─ 드롭다운
      ├─ 전체
      ├─ 식비
      ├─ 교통비
      └─ ...
```

**예상 작업 시간:** 1-2시간

## 참고사항

1. **URL 쿼리 파라미터 활용**

   - 필터 상태를 URL에 저장하여 공유 가능하게
   - 브라우저 뒤로가기/앞으로가기 지원

2. **성능 고려**

   - 카테고리 필터링은 클라이언트 사이드 (이미 로드된 데이터)
   - 기간 필터링은 서버 사이드 (API 호출 필요)

3. **UX 개선**

   - 필터 적용 시 로딩 상태 표시
   - 필터링된 결과 개수 표시
   - 필터 초기화 버튼 제공

4. **접근성**
   - 키보드 네비게이션 지원
   - 스크린 리더 지원 (aria-label 등)
